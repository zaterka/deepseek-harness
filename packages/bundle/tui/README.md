# `@deepseek-ai/dsh-tui`

English | [中文](README.zh.md)

The dsh interactive terminal bundle, launched with `dsh --profile tui` (alias `dsh tui`). [`cordis.patch.yml`](cordis.patch.yml) rides directly over [`dsh-base`](../base/README.md), the same host-plane composition as [`dsh-headless`](../headless/README.md): it supplies the coding persona and tool mode, disables HMR, mounts Code Mode's worker as a core execution capability, and inserts `tool-ask-user` alongside two of this package's own plugins — `tui-startup` (`@deepseek-ai/dsh-tui/startup`, resolved from the injected `cmdlineArgs`) and `tui-client` (`@deepseek-ai/dsh-tui`, config `{resumeSessionId, provider, model}`, resolved from the injected `tuiStartup` provider). It mounts no Host, HTTP server, Web runtime, or browser plugin.

The startup provider ([`src/startup.ts`](src/startup.ts)) parses the optional `--resume <sessionId>`, `--provider <provider>`, and `--model <model>` flags plus this app's own `--help`, then publishes `tuiStartup`; a missing flag resolves to `undefined` rather than a default. The client injects that service and reads its config from lazy fields, so nothing creates an Agent before flag resolution and `dsh --profile tui --help` starts no session. At boot the client creates one fresh persisted Agent through `ctx.agents`, or, when `--resume` names a session the injected `sessionPersistence` still lists, inspects and renders that session's compact history before resuming it through the registry's own durability `prepare()`; a `--resume` target the persistence no longer lists falls back to a fresh session and writes a warning to stderr. `--provider` and `--model` override the shared [`ctx.agentDefaultModel`](../../core/agent-default-model/README.md) selection for this session only; an unregistered `--provider` writes a diagnostic naming the registered routes and exits non-zero, because a bad route has no sane fallback. The client prints `session: <id>` once the loop is ready.

At idle the loop shows a `❯ ` prompt on a [`node:readline`](https://nodejs.org/api/readline.html) REPL. A typed line becomes a user turn: it is submitted to the live Agent through `followup(userMessage)`, then the loop awaits `whenIdle()` before re-prompting. While a turn is live, assistant text streams to stdout as raw `assistant/chunk` deltas, so a multi-delta reply reads as one continuous paragraph the terminal wraps rather than one line per token; a step that streamed nothing falls back to its whole `assistant/message` text. Tool calls and results print as compact one-line cards (`→ name(…)`, `← ok`/`← <code>: error`), closing any open streamed paragraph first. Turn boundaries render as a single blank line between exchanges, with no turn counter. On an interactive terminal the typed line is not echoed again, because readline already showed it at the prompt; a non-TTY (piped or scripted) stdin does not echo, so there the transcript prefixes each user message with `> `. A leading `/` dispatches through the shared [`ctx.commands`](../../interaction/commands/README.md) registry instead of starting a turn: `/help`, `/status`, `/clear`, `/quit`, `/exit` all run there, alongside every command a composed plugin registers (`/plan`, `/compact`, …); `/model` reports the live `provider/model` route and, given `[provider/]model`, switches it for the next turn by mutating the Agent-scoped selection [`installModelSelection`](../../core/agent/src/model-selection.ts) reads at each step — so the live Agent, its session id, and its history are preserved rather than replaced, and the loop's own `request/header` event records the changed route in the durable log. Only the provider is validated against the registered routes, because a provider catalog is advisory and never governs request routing, so an uncatalogued but valid model id must still be accepted; `/resume` answers that it is not available mid-session and points at the `--resume` startup flag, because swapping the live Agent handle without restarting the client is out of scope. Permission requests and `ask_user_question` prompts render on the same terminal, through the [`ctx.userQuestions`](../../interaction/user-questions/README.md) provider and an `approval/request` waterfall listener this client registers, and both read their answer from the loop's shared readline interface rather than opening a second stream over the terminal. Ctrl-C during a turn cancels the agent and returns to the prompt; Ctrl-C again while idle exits after a `press Ctrl-C again to exit` warning on the first press. The durable session log (`sessions.flush(agent.session)`) is flushed after every settled turn or command, and once more before an exit request commits, so progress survives a later forceful kill. Every exit request — two idle Ctrl-C presses, EOF on stdin, `/quit`, `/exit`, or an unexpected driver failure caught at the plugin boundary — closes the readline interface, releases `stdin`, and resolves through the launcher-provided `ctx.appExit` host hook ([`dsh-cmdline`](../../boot/cmdline/README.md)), then terminates the process. The termination is required, not redundant: `appExit` disposes the tree and sets `process.exitCode` for a surface whose event loop drains on its own, while this long-lived surface keeps the launcher's signal handlers and profile-patch file watchers alive, so an exit request would otherwise leave the process running at a dead prompt. An unexpected failure also writes `dsh: <message>` to stderr. Booting this profile outside the `dsh` launcher, without that hook, fails loud at activation.

## Model Experience

None, as the client submits typed lines as ordinary user messages and renders the resulting session events on the terminal; prompts and tools belong to the composed base and any inserted rows.

#### KV Cache effect

None; the client adds nothing to the request prefix.

## Known Limitations and Deferred Work

- **`/resume` is startup-only** — a running session cannot switch to a different persisted session; the command answers with an error naming the `--resume` flag, because swapping the live Agent handle would require tearing down and re-registering every terminal-owned provider and command this client installs.
- **`/model` does not change the stored default** — a switch applies to the live session only and never calls `agentDefaultModel.saveSelection()`, so a session-scoped override cannot silently rewrite the deployment's default for future Agents; set the default through settings instead.
- **`/model` does not validate model ids** — only the provider route is checked. A typo in a model id is reported by the provider at request time rather than by the command, because a catalog is advisory and rejecting an uncatalogued but valid id would refuse legitimate routes.
- **No `reasoningEffort` flag or command** — a startup selection's inherited reasoning effort is preserved across a `/model` switch, but neither the flags nor the command can set it; deployments that need a specific effort set it on the composed default.
- **A streamed step past 1,024 chunks loses its tail** — the renderer stops emitting `assistant/chunk` text once one assistant step has rendered 1,024 chunks (see [`TranscriptRenderer`](src/client/renderer.ts)), and because at least one chunk already rendered, the step's closing `assistant/message` text is not printed either; a step this long shows only its first 1,024 chunks.
- **`ctx.appExit` is launcher-owned** — booting the tui profile outside the `dsh` launcher fails loud at activation until the host provides the exit request.
